================================================================================
REKOMENDACJA: PLAN SCALONY
================================================================================

Wziac szkielet architektury i ~10 taskow z DeepSeek, uzupelnic o:

OD CLAUDE:
  1. Kolumna `namespace` w Room ('' = gosc, uid = konto) - obsluga guest/konto
  2. Warstwa `playback/` oddzielona od UI (StudySessionHolder singleton)
  3. `Clock` injection dla testowalnego czasu
  4. Precyzyjna dokumentacja sciezek Firestore
  5. Kamienie milowe ("po T8 apka do nauki lokalnie")

OD GEMINI:
  6. WorkManager do syncu Firestore (trwaly, exponential backoff)
  7. Credential Manager do auth (bezpieczniejszy niz stary Google Sign-In)
  8. Media3 do audio w tle (najnowszy standard)
  9. Landscape mode dla study screen (nice-to-have, moze byc w polish tasku)

STRUKTURA TASKOW (11, podzielony T10 DeepSeeka na 2):
  T1: Projekt + domain models + utils
  T2: SRS engine + testy
  T3: Normalizer + Merge + testy
  T4: Selectors + Import parsing + testy
  T5: Operations (pure state transformers) + testy
  T6: Room database + Repository + Seed + DI (z namespace)
  T7: Navigation + Theme + Shared UI
  T8: Core screens (Dashboard, Browse, Study) + StudySessionEngine
  T9: Secondary screens (Import, Settings, Archive, Stats, AppSettings)
  T10: Playback (TTS, STT, Media3, audio feedback, haptic)
  T11: Firebase Auth + Firestore schema v2 + WorkManager Sync + Polish
